## 1. Зачем добавлять папку PHP в переменную PATH и как проверить, что PHP установлен?

Переменная среды `PATH` — это список папок, в которых Windows ищет исполняемые файлы,
когда вы вводите команду в CMD. PHP для Windows ставится без установщика (просто
распаковывается архив), поэтому система о нём ничего не знает. Если папку `C:\php`
не добавить в `PATH`, команда `php` будет работать только при указании полного пути
(`C:\php\php.exe -v`), а из любой другой папки CMD выдаст ошибку:
`"php" не является внутренней или внешней командой`.

После добавления `C:\php` в `PATH` (Win+R → `sysdm.cpl` → «Дополнительно» →
«Переменные среды» → системная переменная `Path` → «Изменить» → «Создать»)
нужно **открыть новое окно CMD** — уже открытые окна не видят изменённый PATH.

Проверка установки:

```bat
php -v        :: версия PHP, например PHP 8.3.x (cli)
php --ini     :: какой файл настроек загружен
where php     :: полный путь к найденному php.exe
```

В выводе `php --ini` строка `Loaded Configuration File` должна указывать на
`C:\php\php.ini`. Если там `(none)` — PHP не нашёл файл настроек: проверьте, что
`php.ini` лежит рядом с `php.exe` и не называется случайно `php.ini.txt`.

## 2. Какой командой запускается встроенный сервер PHP и как указать другой порт или корневую папку?

Встроенный учебный веб-сервер запускается командой:

```bat
php -S localhost:8000
```

Сервер обслуживает **текущую папку** (корень сайта), поэтому перед запуском нужно
перейти в папку проекта: `cd /d C:\projects\filemanager`. Остановка — `Ctrl+C`.

Варианты команды:

| Команда | Что делает |
|---|---|
| `php -S localhost:8080` | другой порт, если 8000 занят (`Failed to listen on localhost:8000`) |
| `php -S localhost:8000 -t C:\projects\filemanager` | корневая папка задаётся ключом `-t`, запускать можно из любого места |
| `php -S 0.0.0.0:8000` | сайт доступен с других компьютеров локальной сети |
| `php -d upload_max_filesize=20M -d post_max_size=25M -S localhost:8000` | временная замена настроек php.ini только для этого запуска |
| `php -S localhost:8000 -c C:\projects\filemanager\php.ini` | запуск со своим файлом php.ini |

Важно: после любого изменения `php.ini` сервер нужно перезапустить (`Ctrl+C` и
снова `php -S ...`), иначе новые настройки не применятся. Открывать сайт нужно по
адресу `http://localhost:8000`, а не как файл `file:///...` — иначе браузер покажет
исходный код PHP вместо результата его работы.

## 3. Почему форма загрузки не работает без enctype="multipart/form-data"?

Атрибут `enctype` задаёт способ кодирования тела HTTP-запроса. По умолчанию форма
отправляется как `application/x-www-form-urlencoded`: все поля превращаются в одну
текстовую строку вида `поле1=значение1&поле2=значение2`. Такой формат рассчитан
только на текст — двоичное содержимое файла (байты картинки, PDF, архива) в него
не помещается. Без правильного `enctype` браузер передаст лишь **имя файла как
обычную строку**, сам файл отправлен не будет, и массив `$_FILES` окажется пустым.

`multipart/form-data` разбивает тело запроса на отдельные части (границы —
boundary). Каждая часть имеет собственные заголовки (`Content-Disposition` с именем
поля и именем файла, `Content-Type` с MIME-типом) и может содержать любые двоичные
данные. Именно такие части PHP разбирает и складывает в `$_FILES`.

Поэтому форма загрузки обязательно пишется так:

```html
<form action="upload.php" method="post" enctype="multipart/form-data">
    <input type="file" name="userfile">
    <button type="submit">Загрузить</button>
</form>
```

Метод тоже обязателен `POST`: у GET-запроса нет тела, передавать файл негде.

## 4. Какие ключи содержит массив $_FILES['userfile'] и что хранится в tmp_name?

Ключ `userfile` совпадает с атрибутом `name` поля формы. После отправки PHP
заполняет массив:

| Ключ | Что хранится | Пример |
|---|---|---|
| `name` | исходное имя файла на компьютере пользователя | `report.pdf` |
| `full_path` | относительный путь (PHP 8.1+, при загрузке папок; обычно совпадает с `name`) | `report.pdf` |
| `type` | MIME-тип, который **прислал браузер** (ему нельзя доверять — легко подделать) | `application/pdf` |
| `tmp_name` | полный путь к временному файлу на сервере | `C:\Windows\Temp\php1A2B.tmp` |
| `error` | код ошибки загрузки, `0` (`UPLOAD_ERR_OK`) = успешно | `0` |
| `size` | размер файла в байтах | `245760` |

**`tmp_name`** — это путь, куда PHP сохранил принятые байты файла на время
обработки запроса. Браузер не передаёт файл «прямо в папку проекта»: сначала PHP
принимает его во временную папку (по умолчанию системная, например
`C:\Windows\Temp`, задаётся директивой `upload_tmp_dir`), а скрипт должен успеть
перенести его в постоянное хранилище функцией `move_uploaded_file()`. Временный
файл **удаляется сразу после окончания скрипта**, поэтому, если его не переместить,
загрузка будет потеряна.

## 5. Чем move_uploaded_file() отличается от copy()?

`copy()` просто копирует любой файл, доступный процессу PHP, — она не проверяет,
откуда этот файл взялся. `move_uploaded_file()` перед перемещением проверяет, что
исходный файл **действительно был загружен через HTTP POST** (та же проверка, что
делает `is_uploaded_file()`). Если файл загруженным не является, функция вернёт
`false` и ничего не сделает.

Это защита от подмены пути: злоумышленник, способный повлиять на значение
`tmp_name` (например, через уязвимость в коде), мог бы заставить скрипт скопировать
`copy()`-й произвольный системный файл (`C:\Windows\win.ini`, `/etc/passwd`) в
доступную из браузера папку и прочитать его. С `move_uploaded_file()` такой номер
не пройдёт — системный файл не является загруженным через форму.

Дополнительно `move_uploaded_file()` корректно переносит файл между разными
дисками/разделами (временная папка и папка проекта могут быть на разных томах) и
применяет права доступа, подходящие для загруженных файлов. Поэтому для загрузок
используют именно её, а не `copy()` или `rename()`.

## 6. Чем отличаются директивы upload_max_filesize и post_max_size? Какое значение должно быть больше и почему?

- **`upload_max_filesize`** (по умолчанию `2M`) — максимальный размер **одного**
  загружаемого файла. При превышении файл не принимается, а в
  `$_FILES['userfile']['error']` приходит код `1` (`UPLOAD_ERR_INI_SIZE`).
- **`post_max_size`** (по умолчанию `8M`) — максимальный размер **всего тела
  POST-запроса**: все файлы формы + все текстовые поля + служебные данные
  multipart-кодирования (границы, заголовки частей).

**`post_max_size` должен быть больше `upload_max_filesize`**, потому что файл
передаётся не сам по себе, а внутри POST-запроса: к его байтам добавляются поля
формы и служебные данные multipart. Если `post_max_size` окажется меньше или равен
пределу одного файла, то файл, формально проходящий по `upload_max_filesize`,
всё равно будет отклонён целиком — и даже без понятного кода ошибки (см. вопрос 7).

При множественной загрузке `post_max_size` должен вмещать **суммарный** размер всех
файлов. Общее правило соотношения директив:

```
memory_limit ≥ post_max_size > upload_max_filesize
```

В проекте итоговые значения: `upload_max_filesize = 20M`, `post_max_size = 25M`,
`memory_limit = 128M`.

## 7. Что произойдёт с массивами $_POST и $_FILES, если запрос больше post_max_size?

Оба массива — **и `$_POST`, и `$_FILES` — будут полностью пустыми**. PHP отбрасывает
всё тело запроса целиком, ещё до запуска скрипта, и пишет в журнал сервера
предупреждение вида:

```
Warning: POST Content-Length of 4194498 bytes exceeds the limit of 3145728 bytes
```

Коварство ситуации в том, что привычная проверка `$_FILES['userfile']['error']`
**не сработает**: элемента `userfile` в массиве просто нет, кода ошибки `1` тоже
нет — PHP не разбирал части запроса. Признак превышения — пустой `$_FILES` при
ненулевой длине запроса, поэтому в `upload.php` используется проверка (пример 4.3):

```php
if ($_SERVER['REQUEST_METHOD'] === 'POST'
    && empty($_FILES)
    && ($_SERVER['CONTENT_LENGTH'] ?? 0) > 0) {
    // запрос больше post_max_size — сообщаем пользователю
}
```

Практический нюанс, найденный при выполнении работы: при `display_errors = On`
текст предупреждения выводится **до запуска скрипта**, из-за чего
`header('Location: ...')` падает с ошибкой «headers already sent». Решение:
`display_errors = Off` в php.ini проекта (ошибки пишутся в журнал) плюс запасной
редирект через `<meta http-equiv="refresh">` в функции `back()`, если заголовки
уже отправлены.

## 8. Почему upload_max_filesize нельзя изменить через ini_set()?

`upload_max_filesize` (как и `post_max_size`) — директива уровня `PHP_INI_PERDIR`:
она применяется **до начала выполнения скрипта**. Сервер обязан знать предел
размера ещё на этапе приёма и разбора тела POST-запроса: именно тогда решается,
принимать файл или отклонить его. К моменту, когда выполняется первая строка
PHP-кода и мог бы сработать `ini_set()`, файл уже принят (или уже отклонён) —
менять лимит поздно, он просто ни на что не повлияет.

Поэтому эти директивы задают только:

- в `php.ini` (с перезапуском сервера);
- ключом `-d` при запуске: `php -d upload_max_filesize=20M -S localhost:8000`;
- в `.htaccess` / `.user.ini` (на Apache / CGI).

А вот директивы уровня `PHP_INI_ALL` — например `memory_limit` и
`max_execution_time` — через `ini_set()` менять можно: они влияют на уже
работающий скрипт. Скрытое поле формы `MAX_FILE_SIZE` тоже не является защитой:
оно даёт код ошибки 2, но легко подделывается на стороне клиента и не заменяет
проверку на сервере.

## 9. Для чего при удалении и сохранении файлов используется basename()?

`basename()` отбрасывает из строки всё, кроме последнего компонента пути, — то
есть оставляет только имя файла. Это защита от **path traversal** (выхода за
пределы папки `uploads`), потому что имя файла приходит от пользователя и ему
нельзя доверять.

При удалении (`delete.php?file=...`) без `basename()` злоумышленник мог бы
передать `?file=../index.php` или `?file=../../windows/win.ini`, и `unlink()`
удалил бы файл сайта или системный файл. С `basename()` строка `../index.php`
превращается в `index.php`, путь собирается как `uploads/index.php`, проверка
`is_file()` не находит такой файл внутри папки загрузок — и ничего не удаляется.
В работе это проверено: попытка `delete.php?file=../index.php` вернула «Файл не
найден: index.php», сам `index.php` остался цел.

При сохранении `basename()` убирает путь, который браузер мог прислать вместе с
именем (старые браузеры присылали полный путь вида
`C:\Users\student\Documents\report.pdf`), и не даёт имени «вырваться» из папки
загрузок. После этого имя дополнительно очищается регулярным выражением
`preg_replace('/[^\w.\-]/u', '_', $name)` — остаются только буквы, цифры, `_`,
`.`, `-`. В связке с `is_file()` и белым списком расширений это делает операции
с файлами безопасными.

## 10. Почему нельзя разрешать загрузку файлов с расширением .php?

Папка `uploads` доступна из браузера (ссылки на скачивание ведут прямо в неё:
`uploads/имя_файла`). Если разрешить загрузку `.php`, злоумышленник загрузит
файл-«веб-шелл», например `shell.php` с кодом `<?php system($_GET['cmd']); ?>`,
и затем откроет его по адресу `http://localhost:8000/uploads/shell.php?cmd=...`.
Веб-сервер не отдаст такой файл как текст — он **выполнит** его как PHP-скрипт.

Это означает удалённое выполнение произвольного кода (RCE) на сервере:
чтение, изменение и удаление любых файлов, доступных PHP, доступ к базам данных
и паролям, рассылка спама, полный захват сервера. Достаточно одной такой дыры,
чтобы вся защита остального кода потеряла смысл.

Защита (в проекте реализована):

1. **Белый список расширений** в `upload.php`: разрешены только
   `jpg, jpeg, png, gif, pdf, txt, docx, xlsx, zip` — всё остальное, включая
   `.php`, `.phtml`, `.php5`, отклоняется. Белый список надёжнее чёрного:
   невозможно предусмотреть все исполняемые расширения и трюки вроде двойных
   (`shell.php.jpg`) при неправильной настройке сервера.
2. Очистка имени (`basename()` + `preg_replace()`), чтобы имя не могло изменить
   путь или обмануть проверку.
3. Дополнительно — `uploads/.htaccess`, запрещающий выполнение скриптов в папке
   загрузок на Apache (эшелонированная защита: даже если файл каким-то образом
   попадёт в папку, он не будет выполнен). В промышленных проектах загрузки
   вообще хранят вне корня сайта и отдают через отдельный скрипт.
